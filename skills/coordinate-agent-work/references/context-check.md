# 上下文取数与交接判断

## 只读取必要元数据

优先使用平台状态/上下文指标。账户额度和任务累计预算是不同指标。

Codex 本地 JSONL 可作为可选后备，但格式和位置不是稳定跨版本API。先通过受支持的会话元数据或准确文件发现确定目标，核对 `session_meta.payload.id`，不要以最新文件猜当前会话。仅在有权读取该会话时使用，不扫描无关聊天，不输出原始聊天、凭据或环境变量。

已观察过的字段：

```text
type=event_msg, payload.type=token_count
payload.info.last_token_usage.input_tokens
payload.info.model_context_window
timestamp
type=compacted
```

流式解析，保留最新事件和最近有效采样的位置；容忍尚未写完整的尾行。解析失败或未识别格式需披露，不能静默当作没有事件。

核对会话ID、采样时间、窗口和适用模型。有效输入/窗口必须为合理非负数且窗口大于0。最新 `info=null` 时，不以0代替；可以报告较早有效采样，但必须标为历史。若此后发生压缩、模型切换或窗口变化，旧比例不代表当前占用。输入大于窗口或字段互相矛盾时标记不一致，不裁成100%。

最近输入/窗口只是请求输入占比：不是当前回复完成后的实时余量，不保证可用输出空间，也不是质量评分。缓存输入不从输入占用里扣除；累计 token 不能作分子。不要直接套用150K或80%通用硬线。

示例：旧采样120000/250000，随后压缩，最新info=null。正确结论是“当前未知；压缩前采样48%”，不能报告“剩余52%”。

## 决策

| 信号 | 动作 |
|---|---|
| 同一任务，关键事实一致，容量支持下一步 | 继续 |
| 平台容量警告或下一步大输出可能超预算 | 缩小读取范围，保存断点，按实际工具能力压缩 |
| 已结束单元，下一项为独立阶段 | 按已批准会话策略准备交接，容量未满也可交接 |
| 第一次遗漏约束或复活旧状态 | 查状态来源、派工冲突和工具问题，纠正并记录 |
| 同类错误纠正后重现 | 安全停点交接受影响角色 |
| 缺凭据、环境故障、权限拒绝 | 处理真实阻塞，换会话不能替代解决 |

压缩或交接后，对照权威文件核对当前任务、最新授权、禁止对象、冻结版本、关键发现和下一动作，再续接。不要从摘要推导新权限。

Resume延续；Compact保留压缩历史；Fork继承历史，不能当成干净上下文。需要干净上下文时，新会话只加载精简交接和必要引用。

主管没有能力直接切换自身时，先保存交接，说明工具限制及用户需要做的具体一步。不要谎称已切换，也不要让用户自行整理材料。
