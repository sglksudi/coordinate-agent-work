# Coordinate Agent Work

让主管负责接续和上下文管理，让用户专注取舍、必要授权与试用。按用户语言沟通。

## 适用边界

本技能提供协作方法，不授予创建代理、发送消息、发布、修改权限或切换模型的许可。使用项目已有角色和授权；工具不可用时明确说明。用户暂停优先于持续推进。简单独立任务无需强行拆成三角色。

## 工作单元

- **恢复事实**：读取唯一有效状态入口及最新用户指令，核对任务修订、实际在途状态、冻结输入和下一责任。不重复派发已完成或正在执行的任务。
- **先查可行性**：依赖环境的工作，在相关写入前核对批准对象、实例身份、真实路径、空间与测试前置。将已知的用户操作集中说明；未知项保持未知。
- **任务契约**：给出用户可见结果、必要上下文、允许对象、禁止项、完成条件和交付位置。任务细节用引用，不转发整个聊天。
- **唯一写入者**：实现者完成实现和必要自检后冻结交付；独立验收者不改被测输入。相关小修沿原任务修订，不为每个状态新开任务。
- **接收并续接**：交付者落盘后主动通知一次。主管核对版本和证据，同轮安排下一已授权动作并确认接手；有真实阻塞则登记负责人和恢复条件。

通知被拒时，报告仍可作为授权内读取的交付渠道。不要重试绕过拒绝，也不要让用户搬报告。先判断拒绝是否同时限制后续派工，不能一概忽略拒绝原因。

## 上下文检查是主管职责

在阶段交付、恢复中断/压缩、出现旧状态错误或处理大输出前，检查相关会话。主管自身也适用。读取 [context-check.md](references/context-check.md) 获取取数与判断细则。

先尝试平台指标；缺少直接工具不等于不可查询，权限允许时可核对精确会话日志。不要拿账户额度、累计 token 或文件大小当当前占用，也不要把输入占比当能力评分。

同一单元且状态可靠可继续；容量压力时保存断点，使用实际支持的压缩能力。独立新阶段按项目已批准的会话策略交接；同类状态错误纠正后再次发生时准备安全交接，不等用户提醒。没有换会话权限则准备可审核交接，不自行接管。

每个交付边界在现有记录中写一行：`上下文决策：继续/压缩/交接；依据；下一责任`。未取得数据写未知，不编阈值或保证收益。

## 验证与停点

区分开发自检、独立技术通过、运行就绪、用户验收。模拟、静态检查、真实服务和用户体验各自说明覆盖范围；跳过不算通过。

按改动风险选择验证。输入未变且环境适用时引用旧证据；复验变更及直接影响面。安全、权限、迁移和并发保留必要独立验证。不能借精简取消既定验收契约。

连续同因失败先复盘方案或环境，不原样重试、不自动升档。等待用户或无真实在途任务时，暂停自己有权管理的自动化；没有后台机制就不承诺持续监控。

用户要求收尾时停止新增派工，保存授权内结果并安全停写。恢复后先查断点。交付通知本身不解除暂停。

## 交接与文件

使用项目已有状态文件和临时目录，不再建立第二套台账。需要任务卡、操作卡或交接时读取 [handoff-templates.md](references/handoff-templates.md)。

交接包含关键发现、失败方法及决策原因，不只列完成状态；已有方案和证据只引用。旧方停止相关写入，新方只读核对并接手后，再转移唯一责任。冻结验收中不做常规换人。

阶段结果向用户说明：做成什么、现在能用什么、还缺什么、下一步谁做。观察是否减少催单、重复授权、重复验证和用户提醒换上下文；没有数据不宣称效率提升。
